# Design system and pages

The Graphite look, the UI kit (`mzo_theme.css` + `mzo_ui.js`), the workstation shell, and how to build or change a report page.

## Design system (Graphite)

One look across the workstation and every report: neutral greys, one **fill** colour for primary actions and selected pills, one **accent** (teal in light, blue in dark) for focus, links and the active marker, small **hints of colour** that carry meaning (see [Colour](#colour)), the operating-system font (no web fonts), hairline borders, almost no shadows. Light and dark are equal citizens.

- **Tokens** live in `mzo_theme.css` (`--mzo-canvas`, `--mzo-bg`, `--mzo-surface`, `--mzo-surface-2`, `--mzo-border(-strong)`, `--mzo-text`, `--mzo-text-2`, `--mzo-muted`, `--mzo-faint`, `--mzo-fill` / `--mzo-on-fill`, `--mzo-accent`, `--mzo-ok|warn|bad|info(-soft)`, `--mzo-ok|warn|bad-mark`, `--mzo-c1` … `--mzo-c6`, `--mzo-chart(-muted|-soft)`). `app.html` inlines the same values (it uses `--c1` … `--c6` and `--warn-mark` for the sidebar); keep the two blocks in sync.
- **Theme:** `mzo_theme.js` paints `html[data-mzo-theme="light|dark|ppt"]` before first paint from `localStorage` (`theme`, `mzo_theme`, `collectionDashboardTheme`). The shell also stores `mzo_theme_pref` (`light` / `dark` / `ppt` / `system`) and writes the resolved value to those keys. `ppt` is a light presentation theme for meeting rooms and projectors (mzo_theme.css section 20): light shell chrome, one blue-indigo gradient title band per report, KPI tiles in the six categorical hues (`--mzo-c1…c6`: blue `#2563eb`, orange `#ea580c`, teal `#0d9488`, violet `#7c3aed`, magenta `#db2777`, gold `#a16207`, validated as adjacent pairs) that wrap into balanced rows on desktop, solid blue `#1d4ed8` for selected states, tinted table heads with zebra rows, and larger type (title 30px, panel titles 20px, KPI values 24–34px, tables 15px). Keep every inset at 20px so titles, hints, tabs and the first table column share one edge. **PPT is desktop/projector only:** at ≤900px the shell and `mzo_theme.js` paint a stored `ppt` pref as **light** (the pref is kept so desktop restores PPT), hide the PPT control in the account theme segment and the top-bar PPT button, and phones use Light / Dark / System only with tighter Graphite density (section 22). Inside the shell, `mzo_theme.js` adds `html.mzo-in-shell` (page theme toggles and the floating home button are hidden).
- **Fonts:** `mzo_theme.css` aliases Inter / Outfit / Roboto / Poppins to local system faces (`@font-face … local()`), so Chart.js canvases and older CSS that name those families render in the system UI font without downloading anything. Do not add Google Fonts links.
- **No:** emojis in UI text, gradients, glows, glass blur, coloured left-accent cards, icon tiles, explanatory paragraphs, Font Awesome / Bootstrap / Chart.js on new pages.

### Colour

The base stays neutral. Colour is added only where it carries **identity** (which series, which group) or **state** (how late, how bad), never as decoration. Body text, values and labels stay in the text tokens; a coloured mark (dot, line, bar) sits beside them.

**Categorical palette** (identity). Assign in this order and never cycle: past six series, fold the rest into "Other" or grey them (`UI.line` does this itself).

| Token | Light (hue) | Light | Dark (hue, the PPT order) | Dark | PPT |
|---|---|---|---|---|---|
| `--mzo-c1` | teal | `#12a195` | blue | `#4285f4` | `#2563eb` |
| `--mzo-c2` | blue | `#427fd8` | orange | `#e2671e` | `#ea580c` |
| `--mzo-c3` | plum | `#982c72` | teal | `#13a091` | `#0d9488` |
| `--mzo-c4` | violet | `#886acf` | violet | `#8f63f2` | `#7c3aed` |
| `--mzo-c5` | gold | `#b08505` | magenta | `#e04b95` | `#db2777` |
| `--mzo-c6` | sky | `#0c8bbb` | gold | `#b8891d` | `#a16207` |

Light is validated with the dataviz palette validator (OKLab ΔE ×100, Machado 2009 colour-blind simulation) against the card surface `#ffffff`: all six inside the lightness band and above the chroma floor; worst neighbouring pair under protan/deutan ΔE 14.8 (target ≥ 8); worst neighbouring pair with normal vision 16.2 (floor 15); every slot ≥ 3:1 against the surface and the page background. The first three slots also pass with every pair compared (14.8), so charts where any two series can touch should stay at three. The palette has no green, red or amber, so a series never reads as a status. Dark uses PPT's hue order re-stepped for the dark card, so a chart means the same in dark and PPT; against `#161617` it passes every check (lightness band 0.48–0.67, chroma ≥ 0.10, worst neighbouring pair gold/magenta deutan ΔE 13.5, normal magenta/violet ΔE 20.2) and each slot is 4.5–5.7:1 on the card.

**Dark accents** (mzo_theme.css section 21): dark keeps Graphite's surfaces, type and layout. Each KPI tile (`.ui-stat`) takes its slot hue in order (`--t`) as a 7px dot before its label (a plain `.ui-dot` in the label takes the hue instead; status dots keep theirs); values stay in text ink. The accent is blue `#60a5fa` (7.1:1 on the card): selected stat and drill-tab underlines, focus, links, the checked radio; selected tabs and segments keep their grey pill with a blue hairline and `#dbeafe` text.

**Status colours** (state): text uses `--mzo-ok` / `--mzo-warn` / `--mzo-bad` (≥ 4.3:1 on their `-soft` badge backgrounds, ≥ 5:1 on the surface); dots, bars and chart marks use `--mzo-ok-mark` / `--mzo-warn-mark` / `--mzo-bad-mark` (light `#16a34a` / `#f59e0b` / `#dc2626`, dark the text tokens `#4ade80` / `#fbbf24` / `#f87171`). The mark steps keep amber and red apart (ΔE 24 light, was 9 with the text tokens). Amber is below 3:1 on white by design, and green and red are close for red-green colour blindness, so a status colour always sits beside its label.

When to use which:

- **Chart series** → categorical, in slot order. A single series, share-of-total bars (`UI.bar`) and histograms (`UI.hist`) use slot 1; progress bars (done out of total: connected, installed, rectified) pass tone `2`. The current financial year is always slot 1, last year 2, the year before 3 (`UI.line` does this for the `strong` series). Colour follows the entity, not its rank: when a filter or sort changes the order, give each series a fixed `color`.
- **Identity** → categorical: the sidebar group icons (`hue` in `NAV`: new service connection teal, revenue gold, DD visit sky, consumers & meters blue, vendor advances violet, substation & network plum, Important amber because it means "needs attention"; Media and Administration neutral), and categories that have their own chart (Historical analysis classes).
- **State** → status: delay and age buckets (up to a month ok, up to six months warn, beyond that bad, unless the report has its own rule such as master card 90 days), stat cards that are a state (Connected, Pending, Blocked, Overdue), badges, briefing severity, low stock. Use `.ui-dot.ok|warn|bad` before the label, `.ui-badge.ok|warn|bad` in tables, `dot` on `UI.facet` options.
- **Totals and plain counts** stay neutral; the selected stat and the selected detailed-report tab get the accent underline. In light, keep the teal accent away from green status marks.
- Never mix status and categorical colours in one chart. Grey (`--mzo-chart-muted` or tone `'muted'`) is for "the rest".

**Chart default.** The palette lives in the tokens, so every chart picks it up without page code: `--mzo-chart` is slot 1, and kit charts read it (`.ui-bar` and `.ui-hist` fill with `var(--bar, var(--mzo-chart))`; page CSS charts such as Historical analysis and Weekly use `var(--mzo-chart)` too). In script, `UI.color(tone)` turns `1`…`6`, `'ok' | 'warn' | 'bad'`, `'accent'` or `'muted'` into the right `var(...)`; `UI.bar(v, max, label, tone)`, `UI.hist(el, rows, { tone })` (or `tone` per row) and `UI.line` series `color` all accept it. To recolour a page chart for a selection, set `--mzo-chart` on its container. No page loads Chart.js any more; if one ever does, `mzo_theme.js` only gives it the page font and axis colours, so read `--mzo-c1` … `--mzo-c6` with `getComputedStyle(document.documentElement)` and pass them as dataset colours.

**UI kit (rebuilt pages).** A page opts in with `<html class="ui">` and loads `/mzo_theme.js`, `/mzo_theme.css`, `/mzo_ui.js` (+ `mzo_data_hub.js`, `mzo_scope.js` when it reads data). Structure every report the same way:

1. `.ui-page` → `.ui-head`: `h1` title with the data date as a badge inside it (`<span class="ui-badge ui-date" id="asOn">`), no subtitle; `.ui-actions` on the right. Put a `.ui-side-toggle` **Filters** button in the markup (any place in the head is fine); `UI.sidePanel` moves it to the **first** slot of `.ui-actions` so every page shows Filters in the same spot. The filter panel starts **hidden** (desktop `side-collapsed`, phone sheet closed). Shortcut **F** toggles it.
2. `.ui-layout` → `aside.ui-side#side` (left filter panel) + `.ui-main`. The panel holds, with no field labels: `.ui-side-h` (Filters, “n on”, ghost **Clear**, close), a `.ui-side-stack` with search, then one `.ui-side-sec` per facet. Offices are not in the panel; they are walked in the detailed report (item 4). Facets are `UI.facet(el, [{value, label, count}], current, onChange)`: radio rows with counts, click again to clear, no “All” row. Count each facet on every other filter but itself (`base(skip)`). Related facets share one section as tabs: `.ui-seg.ui-side-tabs[data-tabs]` with `data-pane="<facet id>"` buttons; a tab whose facet is set shows a dot. `UI.sidePanel({ side, toggle, label, count, clear, onClear })` wires toggle, tabs and Clear and returns `setActive(nOn, { paneId: isSet })`.
3. Inside `.ui-main`: `.ui-stats` (one strip, 3–7 `.ui-stat` buttons; columns fit automatically). A stat toggles a filter on the lists below; the stats themselves count the panel filters only.
4. **Detailed report**: one `.ui-panel` with one table that walks Region → Division → CCC (→ any extra level, e.g. Agency) → the rows themselves. `UI.drill({ el, root: 'Malda Zone', levels?, lists?, onChange })` draws the level tabs and the office trail (“Malda Zone / Raiganj / Islampur”) into `el`; the trail *is* the office filter. Pages filter with `dr.match(row)` (rows carry `_region` / `_divn` / `_supp`), group the current level with `dr.key(row)` / `dr.parent(row)`, open a row with `dr.open(name, row)`, render `APP_COLS` when `dr.isList()`, and call `dr.paint({ list: n })`. A tab lists that level inside the path above it; a crumb goes back up. The login scope pins the levels it covers (shown in the trail, not clickable) and the report starts one level below. Deep links `?region= ?division= ?ccc=` go through `dr.fromParams(params, rows)`. Reset table state (`el.__ui = null`) when the level changes. Export CSV exports the rows under the current path and filters.
5. Anything else (e.g. Recent activity on the disconnection tracker) goes below the report. Distributions that used to be `UI.hist` panels belong in the side panel as facets.

Helpers worth knowing (all on `window.UI`, documented at the top of `mzo_ui.js`): `UI.load(key, render)` paints from IndexedDB at once and re-renders when DataHub has a newer body; `UI.refresh(btn, key, onText)` wires a refresh button (forced version check, spinner always cleared); `UI.office(code, name)` maps a CCC code/name to canonical `{ region, division, ccc }` via `MzoScope`; `UI.offices(rows, label)` and `UI.uniq(rows, key)` fill the region → division → CCC selects on pages that still have them; `UI.drawer(title, sub, pairs, extraHtml, actionsHtml)` opens the row detail drawer; `UI.exportCsv`, `UI.copy`, `UI.toast` do what they say. When a kit page is opened outside the shell, `mzo_ui.js` loads `/auth.js` (login gate); inside the shell the shell checks the session. ## Workstation shell (`app.html`)

The only home: login opens it, and `/` and the old phone hub URL `/index.html` redirect to it. It is the same app on desktop and phone.

- One registry (`NAV` in `app.html`) drives the sidebar, ⌘K / Ctrl K / `/` search, and `#hash` routes (`#nsc`, `#loss`, … — keys kept from the old shell). Special keys: `#home` → `home.html` (DISHA launch: mark, full name, instant clickable report tiles that rotate through a larger pool while you stay on the page / favourites / recent — no dataset peeks; live numbers live on Briefing), `#briefing` → `executive_briefing.html` (detailed scorecard), `#collect` → `collect/` (DISHA Collect inbox; shell top-bar pill + sidebar badge when pending). Administration shows only for `role: admin`; **Sheet links** only with `sheets-autho` list/edit/y/all.
- Pages open in iframes that stay alive (5 on desktop, 2 on phones / low-memory devices), so switching back is instant. Hovering a link prefetches its HTML. A thin top progress bar shows while a page loads; the page paints underneath.
- Pages can call `parent.openPage(url, title)` to jump to another report (the briefing does). If a page navigates itself to another report the shell follows it; if it lands on `/login.html` the shell signs out to the login page; a Home link (`/app.html`, or the old `/index.html`) goes to **Home** (`home.html`) instead of loading the shell inside itself.
- Sidebar collapses to a rail (⌘B / Ctrl B, remembered in `mzo_ws_rail`); on phones it is a drawer (opened from the top bar, the **Browse** tab, or an edge swipe from the left). A highlighted **Favourites** card (`mzo_ws_favs`) sits at the top of the sidebar so users can pin frequently opened reports via the star button on any report row, in the top bar (`#favPageBtn`), or in the command palette (`⌘K`). On phones (≤ 900px) the shell shows a Material 3 bottom navigation bar (**Home · Saved · Search · Ask · Browse**), collapses the top bar as the active report scrolls down, opens search (`#pal`) as a full-screen view with a back button, and pushes a history entry for the drawer or search so the Android Back gesture closes them before leaving the report. Account menu theme on phones: Light / Dark / System only (PPT is hidden and coerced to Light); on desktop the menu still offers Light / Dark / PPT / System. Sign out (`POST /api/logout`). Recent reports: `mzo_ws_recent`.
- The service worker does not inject `mzo_present.js` into `app.html`; each report keeps its own zoom control.
- On the VM (mirror mode) the shell asks for the data manifest once before its first frame loads, so frames reuse it, and shows a quiet **Data as of <time>** in the top bar (muted 12px text, hidden on phones; the tooltip gives the date). That time is when the server last checked its sources (`generatedAt`). In idle time it refreshes datasets this device already keeps whose server copy changed: up to 8 on desktop, up to 3 under 1.5 MB on phones, none on data saver or 2G. Without a mirror (Vercel) none of this shows or runs.

## Adding a report page

1. Build it on the UI kit (see **Design system**): `<html class="ui">`, kit structure, `UI.*` helpers. Register it in the shell `NAV` in `app.html`; that is the only place a page is listed.
2. Include `/mzo_data_hub.js` and `/mzo_scope.js` with the same `?v=` the other pages use (bump it everywhere when the file changes).
3. Add the **Google** (or other origin) URL to `DATASETS` in `mzo_data_hub.js`. Load with `UI.load` (or `waitForDataset` then `_peek`) — never a raw sheet `fetch` if a DataHub key exists, and never an `/api/.../dataset` body proxy.
4. After load: `rows = MzoScope.filterRows(rows)`. Office navigation is the detailed report's trail (`UI.drill`), which pins the login scope itself; pages that still have office selects fill them with `UI.offices` and pin them with `UI.lockScope()`.
5. Add the path to `sw.js` `isNetworkFirstPath` and bump `CACHE_NAME`.
6. If the folder is new, add it to `vercel.json` `builds`.
7. **Mobile (Graphite Material, `mzo_theme.css` section 22 + `mzo_ui.js`):** below 980px the side panel hides behind the **Filters** button; on phones (≤ 760px) `UI.sidePanel` and `UI.drawer` open as bottom sheets with a drag handle, scrim, sticky action bar, drag-to-dismiss, `navigator.share` on row details, and `history.pushState` so Android Back closes the sheet first. The `.ui-stats` strip becomes a horizontal snap carousel of tonal cards. At ≤ 600px, `UI.table` renders rows as a tonal card list with a sort chip bar (`cfg.cards: false` opts a table out). Touch devices also get Material state-layer ripples and pull-to-refresh on pages that wire `UI.refresh`. Keep the header to one title line.
8. Verify light, dark, inside `app.html`, and at phone width (~390px). Login-gated pages cannot be checked with anonymous `curl` of the HTML.

## UI conventions

- New and rebuilt pages use the UI kit (see **Design system**). Do not introduce a new CSS framework on one page.
- Sticky chrome stays thin on phones; overlays must not grow the sticky box (`position: absolute` / `fixed`, not in-flow). Kit pages use the kit header, the left filter panel (opened from **Filters** below 980px) and one stat strip.
- A stat card filters the detailed report below it, never the other stat cards: every card counts within the panel filters and the office path. Status cards show the count with its share on one line (`5,182 · 26%`) and an amount on the next where one exists (Disconnection Tracker is the reference). Follow-up notes (Disconnection Tracker, Pending NSC) live in the row drawer and in a **Follow-ups** tab of the detailed report: one row per consumer or application, opening the notes newest first with author and date. Only an admin (`mzo_user_profile.role` is `admin`) sees the delete control.
- **Presentation toolbar & zoom** (`mzo_present.js`): desktop only (width ≥ 900px), fixed bottom-right (`#mzo-present-zoom`) as a compact horizontal pill: **PPT** · **−** · **%** · **+**. PPT uses `MzoTheme.togglePpt()` (shortcut `P`). Zoom is 75–175% in steps of 10 (`mzo_present_zoom`, shortcuts `+` / `-` / `0`); tap the % label to reset to 100%. **F** toggles the filter panel (not slide-focus). Do not add a second zoom control on report pages. Zoom stays inside the page’s existing scroller so the window does not gain a second vertical scrollbar. Power Map and the accident map keep their own pan/zoom. Phones stay at 100% and the control stays hidden.
- When a dashboard mixes **counts-only** KPIs and **named-row** KPIs, split them into two labeled bands (Count vs Names). Use one card style. Count-only rows must not open a names modal. Defective Meter is the reference.
- **Durga Puja (`puja.html`)**: sidebar **Important → Durga Puja 2026**. A compact selector for *Format-I*, *Format-II* and *Hourly Load* (2025 / 2026) that opens the chosen sheet in an embedded viewer; *Format-I 2026* opens first.
