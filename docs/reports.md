# Report notes

Per-report rules that are not obvious from the code: data sources, date cells, who can sync, special cases.

## Sheet links

Sidebar **Important → Sheet links** opens `sheet_links.html`. The page does not add its own home button or a second title. The item is hidden unless the user is `admin` or `sheets-autho` is `list`, `edit`, `y`, or `all`. The page is a numbered table of Google Sheet links only (not Supabase, JSON, Script, or RSS). Each row opens the spreadsheet and copies that Google link. When the file id is known, the link is `https://docs.google.com/spreadsheets/d/{id}/edit?gid={gid}#gid={gid}`. A published-only sheet stays on its published page. **Updated** is filled when a date is already known: DataHub `mzo_hub_ver_*` (`m:` Last-Modified or an ISO time), `/api/hub/versions`, NSC/Withheld meta, defective upload meta, or stock meta. Disconnection Tracker uses the same date as that page’s header: the latest `PAID/DISCON DATE`, shown as `dd/mm/yyyy`. Docket Calls uses the same day as “Upto docket at”: the latest `doc_crn_dt`, shown as `dd/mm/yyyy`. CMO Grievances uses the same “Report as on” value as that page’s header (`Report Date`). Collection Report uses the end of the header period, the latest payment date. Stock Metadata uses the stock page header date, “Stock of Major Materials (dd/mm/yyyy)”, from the stock report date. CAPEX Details uses the same “Report updated on” date as that page’s header: the latest `Reporting Date`. Pending Master Card uses the same “As on” date: the latest `Report Date`. O&M Advance uses the same “Report updated on” date as that page’s header: the latest `Creation Date`. Bharat Net uses cell **N2** (`UPADTE DATE` / `UPDATE DATE`, `dd.mm.yyyy` in the sheet), shown as `dd/mm/yyyy` — the same label as that page’s header “As on”. Loss Report uses cell **J2** (`Update On`, `dd.mm.yyyy` in Sheet1), shown as `dd/mm/yyyy` — the same label as that page’s header “As on”. Feeder Outage uses the latest `REPORT MONTH` (`YYYYMM`), shown as the last day of that month. JJM Connections shows **As updated by RMs** instead of a date. Every other Updated cell uses `dd/mm/yyyy`. Otherwise the cell stays an em dash. Stock and Power Map are omitted while their source is not a Google Sheet. Vendor Map, PMSGY Data 0, 1, and 2, Loss Targets, Manpower, and Highway Crossings are left off this list. NSC and Withheld use fixed edit URLs when `/api/nsc/meta` is slow. Admin → user form → **Sheet links** = Yes stores `list` (the sidebar item only). **Sheets** = Manage stores `edit`, which also shows the item and can manage Important Sheets. `''` shows neither the item nor manage. NSC upload and other report grants do not show the item. Column is existing `mzo_insight.portal_users.sheets_autho` (`scripts/sql/upgrade_existing_tables.sql`). `canManageImportantSheets` still treats only `edit` / `y` / `all` (and admin) as manage. Network-first: `/sheet_links.html`.

## NSC upload

`/nsc/upload.html` turns the raw SAP Excel into clean rows **in the browser** (`nsc/nsc_client_pipeline.js`) and writes them to Google Sheets through Apps Script (see [apps-script.md](apps-script.md)); NSC rows are no longer stored in Supabase.

- Working/Accepted rows go to the `nsc_working` tab, one row per `APPL_NO` (last row wins). A Working/Accepted row stays here even if a withheld date or reason is still filled.
- Withheld rows go to the `NSCWH` workbook, `Sheet1`. If the file has **no** Withheld rows, the upload does not clear that sheet and keeps the previous Withheld meta.
- A small version record (who, when, row counts) is kept in Apps Script document properties.
- Who can upload: admins, the `nsc_upload_autho` flag (Admin → User Management → **NSC Raw Upload**), or the legacy username `dm1`.

## Bharat Net

## Feeder Outage

Page: `feeder_outage.html` (sidebar Substation / Network, DataHub `CACHE_FEEDER_OUTAGE`). DataHub URL is the published Google CSV (`pub?gid=0&single=true&output=csv`). The browser fetches it; do not proxy through Vercel. After load: `MzoScope.filterRows`. `CIRCLE NAME` is the region (MALDA → Malda, UTTAR DINAJPUR → Raiganj, DAKSHIN DINAJPUR → Balurghat) and `DIVISION NAME` is the division; the page writes `REGION_NORM` and `DIVISION_NORM` before `filterRows`. There is no CCC column. Duration is minutes of outages over 5 minutes in `REPORT MONTH` (`YYYYMM`). Average daily is that month’s minutes divided by the days in the month. Monthly range is the lowest to highest month’s average hours per feeder (one month shows that month, plus the feeder spread). Yearly average is the mean of the monthly averages in the latest calendar year on the sheet, not a forced 12-month figure. A feeder is a concern when that month averages at least 1 hour a day, or has 30 or more outages, or (once an earlier month exists) is at least 50% and 2 hours above its own previous month. The page calls `waitForDataset('CACHE_FEEDER_OUTAGE', { forceCheck: true })` so a same-day replace of the published CSV is downloaded again (Google’s published file has no ETag, and a normal page open would otherwise keep that day’s IndexedDB copy). The browser fetch uses `cache: 'no-store'` for Google sheet hosts. Sheet links **Updated** uses the latest `REPORT MONTH`, shown as the last day of that month (`dd/mm/yyyy`). The month chips sit under the office filters. Chart and Data table are the two views of one cut: All, Region, Division, SS, or Feeder. The chart is average outage hours per feeder on a month–year axis. The table lists that same cut, high to low. SS and Feeder lines on the chart are the 12 highest; the table lists every row. The page uses the Disconnection Tracker chrome.

## Disconnection tracker

Page: `disconnection.html` (DataHub `CACHE_DISCONNECTION`). Uses `originHeavy: true` with `versionUrl: /api/disconnection/meta`. Snapshot CSV is mirrored to Supabase Storage (`reports/disconnection/snapshot.csv`) via `npm run sync:disconnection` (`scripts/sync/sync_disconnection_to_supabase.js`) or via the in-app **Sync sheet** button (`#cloudSyncBtn` → `POST /api/disconnection/sync`). Authorized users (Admin, username `dm1`, or users with `disconnection-sync-autho` = `Y` set via Admin → User Management) see **Sync sheet** in the header; unauthorized users only see the normal local refresh button. The page paints from IndexedDB first and refreshes when Storage has a newer copy. If Supabase is unavailable, it cleanly falls back to the published Google CSV.

The left panel holds search, **OSD above ₹3,000 / ₹5,000** and class, with the DOM and IND/COM OSD base dates at its foot; on a phone it opens from **Filters**. The detailed report walks Region → Division → CCC → **Consumers**, with a **Follow-ups** tab (Last 7 days / All) for the same office path. The status cards (paid, part paid, disconnected, no action) filter the breakdown and lists and count within the panel filters, so “no action, OSD above ₹5,000” is one click each. Follow-ups live in the consumer modal and on the **Follow-ups** tab, newest first, matched on the trimmed consumer number (`CON_ID` / `c.id`). Each note stores the signed-in user's **Name** (`mzo_user_profile.Name`, or Username if Name is blank) and the save time. Replacing the consumer dump does not clear them.

Save paints the new note at the top of the open list and clears the box in the same click, into `localStorage` (`mzo_discon_followups`). The sheet write (`mzo_discon_followup_outbox`) starts only after that paint. A slow or failed write retries in the background. A row with no consumer number cannot save a follow-up. Pending NSC uses the same order: the note appears and the box clears before `mzo_nsc_followup_outbox` is sent.

Shared copy is a **Followups** tab via `apps-script/disconnection_followup.gs` (append and soft-delete, not a republish of the consumer dump). Soft-delete is an admin action on the page. `GET /api/disconnection/meta` returns `sheetScriptUrl` from `DISCONNECTION_FOLLOWUP_SCRIPT_URL` (the Followups web app; env overrides the default `/exec` URL), plus `version`, `stats`, and `csvUrl`. The open page pulls the comment list about every 15 seconds, when the tab becomes visible, and when a consumer modal opens. That pull refreshes the follow-up list only. It does not reload the disconnection CSV. Do not proxy the comment sheet through Vercel.

Pending NSC (`nsc.html`) uses the same follow-up rule on the trimmed application number (`APPL_NO`), in its own store `mzo_nsc_followups` and outbox `mzo_nsc_followup_outbox`. Paste `apps-script/nsc_mirror_and_followup.gs` over the existing nsc_working Apps Script and deploy a new version of that same web app. `GET /api/nsc/followup-meta` returns `sheetScriptUrl` from `NSC_FOLLOWUP_SCRIPT_URL` (the same nsc_working `/exec` URL; env overrides the default). A new NSC upload keeps a note when the same application number is still in the file. The Consumer application list shows the CCC name (`SUPP_OFF`). Summary, consumer, follow-up, and top-delayed table headers sort on click. Until a header is clicked, each table keeps its existing order: count for office summaries, delay-range order for the delay tabs, collection date on the consumer list (delay on a phone), newest note on follow-ups, and delay on the top-delayed list. The Follow-ups pill lists those applications in the current filters as a table in the same style as the application list. A row opens the note list, latest first, with the author and date in small text. The delete control is shown only when the signed-in role is admin.

## Defective Meter

Page: `consumer/defective_meter.html` (DataHub `CACHE_DEFECTIVE` & `CACHE_DEFECTIVE_DETAILS`). Uses `originHeavy: true` with `versionUrl: /api/defective/meta`. Summary and details CSVs are mirrored to Supabase Storage (`reports/defective/summary.csv` and `reports/defective/details.csv`) via `npm run sync:defective` (`scripts/sync/sync_defective_to_supabase.js`) or via the in-app **Sync sheet** button (`POST /api/defective/sync`). Authorized users (Admin, username `dm1`, or users with `defective-upload-autho` = `Y` set via Admin → User Management) see **Sync sheet** in the header. The page paints from IndexedDB first and refreshes when Storage has a newer copy. If Supabase is unavailable, it cleanly falls back to the published Google CSVs.

**Who can upload / sync:** `GET /api/defective/meta` → `canUpload` and `canSync`. True if `role` is `admin` (case-insensitive), or portal flag `defective-upload-autho` / `defective_upload_autho` is Y/yes/1/true/upload, or username `dm1`. Admins always can, even if the flag is blank. The page also shows upload from `/api/session-check` / `mzo_user_profile` so a stale cookie without `role` does not hide the button.

**Admin UI:** User Administration → **Def. meter upload** Yes/No. Persist column `mzo_insight.portal_users.defective_upload_autho` (`scripts/sql/upgrade_existing_tables.sql` if the table already exists, then `NOTIFY pgrst, 'reload schema'`). Mapped in `portalUserToClient` / `clientUserToPortal`.

**Upload UI:** file picker + Publish only. Do **not** add setup copy (summary vs details, “processed in this browser”, Open sheet, Apps Script URL). Pipeline: `lib/defective_meter_pipeline.js` → `apps-script/defective_meter_publish.gs`. Network-first: `/consumer/defective_meter.html`, `/lib/defective_meter_pipeline.js`, `/lib/sheet_mirror_client.js`, `/mzo_data_hub.js`, and `/admin_users.html`.

**KPI UI (two data kinds):** Summary tab is counts for every meter; details tab stores names only for priority groups (`DETAILS_FLAG` / `isPriorityMetric()`). Split the dashboard into two bands with one card style (no mixed Bootstrap tints): **All meters / Count** — Total, Agri, >5 yrs, Load 0.5–1, Load <0.5 — tables only, no consumer modal. **Priority / Names** — >10 yrs, 3-Ph, Industrial, Smart, Load >6 / 3–6 / 1–3 — By CCC or By Load drills to the consumer list. Count-only CCC rows must not open the names modal.

Upload the **consumer dump** (one row per meter), not a summary. The parser accepts comma / tab / pipe / semicolon and maps aliases (`CCC CODE` → `CCC_CODE`, `CONS_ID` → `CON_ID`, …). If office columns do not map, every row collapses into one blank-office total — the pipeline rejects that instead of publishing it. Agri = BASE_CLASS `A` (not Rural `R`). Industrial = `I`. Smart = meter no `IJ`/`IL`/`IT` or type SMART — not `ELECTRONIC`. The last dump stored Rural/Urban as class and `ELECTRIONIC` as meter no, so those KPIs were zero; re-upload after this parser.

Portal user SQL/import notes: [database.md](database.md).

## Central Metadata Sync & Report Dates

`apps-script/mzo_metadata_sync.gs` provides a standalone Apps Script template to aggregate report update dates from source Google Sheets (cells `N2`, `M2`, `J2`, or column dates) on a 15-minute background trigger.
- Deploy the script as a Web App (Anyone access) and set `METADATA_SCRIPT_URL` in environment variables.
- `GET /api/hub/versions` in `server.js` automatically merges the returned metadata payload, allowing `sheet_links.html` (`Updated`) to render report update dates in `< 50ms` without probing individual Google Sheets on demand.
